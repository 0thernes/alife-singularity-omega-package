### Errors in the frozen white paper (`paper/main.tex` and `dist/Donahue_2026_alife_singularity_omega.pdf`)

None of these affects a Lean theorem statement.

- **Title (`paper/main.tex` line 34) and section heading (line 179):** "Hardware Ring-0 Constitutional Invariants" and "327 Pure 6-Kernel Lean 4.35.0 Theorems". Correction: no hardware is modelled in Lean; `36` core + `4` Palomar declarations are checked in this package, and the `291` companion-reported theorems are not checked here.
- **Abstract (line 52) and seven-repo section (line 191):** "totaling 327 Pure 6-Kernel Lean 4.35.0 theorems", "0 `sorry` in `lean/`" and "no `Classical.choice`". Correction: `327` is a sum of reported counts; `lean/palomar/PalomarChallenge.lean` contains `4` intentional `sorry` stubs; the `Classical.choice` statement holds for the `40` audited declarations only.
- **Claims table, row C2 (line 86):** tagged kernel-checked for the `291` companion theorems. Correction: cross-repository report, not checked at this commit; Lean checks only `48 + 70 + 89 + 54 + 30 = 291`.

Its Lean counterpart `ring0_kernel_state_invariant` holds because the modelled write function returns its input for every ring, and the model has no Ring-1/Ring-2 state, so it shows no non-interference property.
- **Fidelity table rows M2 and M3 (lines 212-213):** M2 "locking live 7-repo theorem accounting"; M3 "state invariance". Correction: the M2 items are literal sums that certify no data; the M3 state-invariance item is degenerate as described above.

### Known issues in the formal code (not yet fixed)
